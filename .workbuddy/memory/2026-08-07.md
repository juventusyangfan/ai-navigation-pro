## 解决 front (Next.js 16) 云上 build 失败：prerender /literacy 报 fetch failed (ENOTFOUND admin.eanavi.com)

根因：front 的 `/literacy`、`/tool/[slug]`、`/scenes/[key]`、`/usages/[id]` 是服务端组件，`next build` 阶段静态预渲染会触发 `await content.getX()` → 服务端 fetch `admin.eanavi.com`；云上构建机解析不到该域名 → 构建 abort。工作区代码已含 `export const dynamic='force-dynamic'` + `safeFetch`，说明云上跑的是更早的旧代码。

改动（让 SSR 不依赖公网 DNS）：
- `front/src/lib/content.ts` 的 `apiUrl`：base 改为 `process.env.INTERNAL_API_BASE ?? process.env.NEXT_PUBLIC_API_BASE ?? ""`（服务端 SSR 走 localhost，浏览器回落公网域名）。
- `ecosystem.config.js` front env 增加 `INTERNAL_API_BASE: "http://127.0.0.1:3001"`。
- 部署指南 front `.env.production` 增加 `INTERNAL_API_BASE=http://127.0.0.1:3001` 说明。

部署要点：云上需 `git pull` 最新代码 → `rm -rf .next` → `npm run build`；`NEXT_PUBLIC_API_BASE` 必须在 build 前设好（build 时内联）；`admin.eanavi.com` 需 DNS A 记录指向 Lighthouse 公网 IP（供浏览器/客户端 + certbot 使用），运行期 SSR 已改走 localhost 不再依赖它。
