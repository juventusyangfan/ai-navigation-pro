## 修复：AI通识课「进入模块」/课时页报错

### 现象
用户点击「进入模块」(/literacy/what-is-ai) 报 Internal Server Error；复现实测为 HTTP 404（模块页、课时页均 404），首页 /literacy 正常 200。

1. **课时 `ai-in-one-breath` 在数据库中状态是 `draft`**：后台课时详情路由逻辑 `if (lesson.status !== "published") return fail(404)` 直接 404，front 课时页随之 404。该课时是被某种 seed 重跑的 upsert 重置回了 `draft`（seed 默认即 draft，占位官方 URL 的安全默认）。
2. **front 旧服务（PID 3888）是陈旧/异常实例**：admin 模块详情明明返回 200，它却对模块页返回 404，说明旧进程状态错误。

### 修复
- `db.litLesson.updateMany({where:{status:'draft'}, data:{status:'published'}})` → 6 节全部 published，后台课时接口恢复 200。
- `taskkill /PID 3888 /F` 停掉旧 front；以**关闭沙箱** + `NEXT_PUBLIC_API_BASE=http://localhost:3001 INTERNAL_API_BASE=http://127.0.0.1:3001` 重启 `next dev -p 3000`（上次验证可用配置）。

## 修复：后台「编辑模块」点击保存后无效（实为静默降级）

### 现象
用户报 admin 后台『AI通识课 → 编辑模块』点保存无效。浏览器实测（super_admin）PATCH 本身 200 且数据落库 —— 保存并非真正失效。

### 根因（真正 bug）
`admin/src/lib/serialize.ts` 的 `litModuleToCard` / `litLessonToCard` **漏返回 `status` 字段**：
- 编辑页 GET 拿不到 status → 表单 `status` 落到兜底默认值 `"draft"`；
- 点保存时 payload 永远带 `status:"draft"`，把已 `published` 的模块/课时**静默降级回 draft**；
- 降级后模块从公开站（只显 published）消失，用户感知为「保存无效 / 白保存」；
- 后台总览表的「状态」列也因此全部误显为「草稿」。

### 修复
- `serialize.ts`：`litModuleToCard`、`litLessonToCard` 均补 `status: m.status / l.status`，并在 `LitModuleCard`/`LitLessonCard` 接口补 `status: string`。
- 编辑页（modules/[id]、lessons/[id]）保存成功后显示「已保存 ✓」，再次编辑输入框时清除提示，避免「看起来没反应」。
- `modules/[id]/route.ts` 的 PATCH 补 `try/catch`，与课时路由一致，服务端异常返回干净 JSON 而非 500 HTML。
- **RBAC 缺口**：`editor`/`reviewer` 在 DB 中缺 `literacy` 权限（seed.ts 有但库未落），已用脚本 upsert `editor:literacy(read/write/delete)`、`reviewer:literacy:read`（仅增权限行，不碰内容表）。这样非超管也能正常使用通识课后台。

### 验证
- 浏览器实测：加载时状态下拉显示 `published`；只改标题保存 → PATCH body `status:"published"`、落库仍为 `published`，无报错。
- 注意：`next dev` 必须关闭沙箱跑；改动已热重载到运行中的 3001 实例。
